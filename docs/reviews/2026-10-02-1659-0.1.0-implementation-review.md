## Live Run (2026-10-02, PERS scope)

The first run of `bundle exec rake test:live` gave 13 runs: 10 passed, 1 failed, 2 skipped. The skips were `ai_check` and `batches`, which need CORP.

Spec §13 questions:

1. **v2 stream payload shape: settled.** Deltas are `messages[].content[].text`, as in the Python SDK; the spec's `choices[].delta` example is wrong.
2. **`tool_state_id` vs `tools_state_id`: settled after a fix.**
   - The round-trip test failed. A diagnostic call (`tmp/diag_tools_state.rb`) showed that the API returns `tool_state_id` (singular) on the assistant message.
   - **Fix:** `Types::Message#tools_state_id` reads both spellings and is aliased as `#tool_state_id`. The v2 accumulator keeps both keys.
   - **Tests:** `TypesTest#test_message_reads_the_live_tool_state_id_field` and `StreamTest#test_v2_accumulator_keeps_the_live_tool_state_id_field`, each RED→GREEN.
   - **Round trip:** the live test and the README now send the assistant message back unchanged, with a `tool` message that carries only `function_result`. This was the deferred README minor; it is now resolved.
3. **`files.content` `Accept` header: settled.** `*/*` works.
4. **`GET /batches` shape: open.** It needs CORP credentials, and the live assertion still accepts either shape (see the deferred minors).

### Final review: other rulings

| Topic | Ruling | Cost if wrong |
|---|---|---|
| "`break` closes the connection" | No unit test: WebMock can't observe a socket close. The reviewer verified it on a real socket. | A regression would go unnoticed until live use. |
| POST retries on 5xx and `ConnectionFailed` | Kept, as spec §6 mandates; users can pass `max_retries: 0`. | A rare double-billed generation. |
| POST open timeout | Faraday maps it to `ConnectionFailed`, so it **is** retried. POST read timeouts are not retried, because the request may already be billed. | None. |
| Uppercase `/V1` or a query string in `base_url` | Produces a wrong v2 URL; treated as an unusual input. | A v2 chat 404 for such users. |
| `with_options` shares the token manager | It keeps the original config (logger, OAuth TLS); only the token is meant to be shared. | Token-refresh logs go to the original logger. |
| `verify_ssl_certs: false` warning | Repeats for every `with_options` copy, since each copy is a client. | Log noise. |
| String option values set in Ruby | Not converted (only env strings are), since Ruby callers pass typed values. | A confusing Faraday error for `timeout: "60"`. |
| `batches.create` with a `String` | Treated as a path (spec §2). | Users wrap raw JSONL in `StringIO`. |
| Error event as the very first stream event | Not retried: conservative, and it can't duplicate output. | One fewer automatic retry. |
| Unterminated final SSE event | Still delivered at end of stream, as spec §10 requires. | None observed. |
| `Types::Base#dig` | Doesn't convert string keys to symbols; the data is documented as symbol-keyed. | A minor surprise. |
| `client.request(method: "GET")` | The escape hatch expects a Symbol; Faraday rejects a String. | One confusing error. |
| Bad `cert_file` or key password | Raw `Errno` / OpenSSL errors; rare, and the messages are clear. | Less uniform errors. |
| `logprobs` on text deltas | Accumulate as separate content parts (a literal reading of spec §10). | Noisy accumulated content for `top_logprobs` users. |
| Connection pooling | Not done; an explicit non-goal (see the backlog). | A TLS handshake per request. |
| CHANGELOG heading | Stays `[Unreleased]` until the release. | None. |
